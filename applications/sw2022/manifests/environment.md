# Saha--Weeks computational environment

This analysis uses a project-local, native Apple-silicon installation of
R 4.5.3.  It does not alter the system R installation.  The launchers are
`applications/bin/R45` and `applications/bin/Rscript45`; package binaries are
installed below the ignored directory `.R-library/4.5`.

The R framework was extracted without administrator privileges from the
official CRAN installer `R-4.5.3-arm64.pkg`.  Both the CRAN and cloud-mirror
copies had SHA-256 digest
`8c1d5005547926425037ffa7d9062099231e033022275648625b32791dd43eb5`.
The framework is stored in the ignored `.runtime/R-4.5.3-root` directory and
relocated through `/tmp/R45`.  Its Mach-O references to `libR.dylib` were
rewritten to the relocated framework and ad-hoc signed.  The local Rscript
front end delegates to the relocated R executable because the upstream
Rscript binary embeds the system framework path.

The analysis pins the R package `torch` at version 0.16.3 using the
MLverse Apple-silicon CPU binary repository.  All substantive fits use the CPU
backend.  Exact package versions and session information are regenerated by
the application export script and stored beside the fitted results.

The official installer signature could not be evaluated on this host: both
`pkgutil --check-signature` and `spctl` returned subsystem/signature errors for
independently downloaded CRAN copies.  For that reason the installer was not
run with administrator privileges.  The SHA-256 check above and the
unprivileged extraction make this limitation explicit rather than bypassing a
system security decision.

Once no fit process is active, run
`applications/sw2022/bin/postfit_validate.sh` from the package root. The driver
refuses to reinstall while `03_fit_models.R` is running. It reinstalls the
current source into `.R-library/4.5`, refreshes this environment verification,
and records critical runtime/Torch/launcher hashes, all local package versions
and DESCRIPTION hashes, parse and source-text checks, and focused paperps and
native CPU-Torch test results in `manifests/postfit_validation/`.
If the restricted host cannot query the operating-system process service, the
driver fails closed; once the fit session itself has reported completion, pass
`--fit-confirmed-stopped` explicitly.
